# 等待接续隔离规则应用演练

本文件仅分析 `docs/bugs/evidence/subagent-wait/scenarios.md` 的 13 个模拟题设。未调用真实代理、未启动客户端 CLI、未修改源文件、未读取 evidence 目录其他文件或 Git diff。题设中的返回值、状态和配置均是假设输入；以下“下一操作”是应执行的动作描述，不是执行回执。本演练不能证明真实宿主行为或修复效果。

读取规则：`skills/longdev/SKILL.md`、`skills/longdev/references/execution-protocol.md`、`skills/longdev/references/session-runtime.md`。这是受限范围的规则应用演练，并非启动一个 longdev 开发任务，未执行迁移、派发或插件版本探测。

依据简称：

- **等待**：共享协议“子代理等待与接续”。
- **收敛**：共享协议“调查收敛与工具异常”。
- **生命周期**：共享协议“子代理生命周期”。
- **模型**：共享协议“客户端与模型边界”，会话适配“模型配置与路由”。
- **适配**：会话适配“子代理宿主适配”。
- **状态**：共享协议“状态与责任”及 SKILL C 阶段推进流程。

## 1. 三次正常超时后收到完成报告

**下一操作与接续：** 第三次返回时累计 90 秒，小于已记录的 180 秒复核点；继续调用一次不超过 30 秒的 wait，不因达到三次而启动错误调查、不重复派发，也不发送“继续”。题设指定下一次实际返回完成报告，立即读取报告和产物路径，核验文件、交接、自检证据与活动写入；结果满足实现交付条件后衔接独立 checker、reviewer 和主会话 gate。若等待期间先到复核点，则应查询状态/进度，不能把 30 秒时限当复核周期或预算。

**可声明：** 90 秒时“尚未收到完成结果；最近有效状态为执行中，仍在复核点和预算内”。报告到达后可声明“收到实现报告，产物待核验”；核验自检与交付后可置待检查。不能仅凭超时声明 A 此刻仍在运行，不能凭完成报告声明阶段通过、已验收或槽位释放。

**依据与歧义：** 等待、收敛、状态。正常在途等待在复核点前不计入三次无新事实阈值。题设未给报告内容、自检和停止写入证据，因此后续核验结论仍未知。

## 2. wait 与状态查询均为 agent not found

**下一操作：** 停止对该 ID 盲等，保留两次原始返回、最近 executing 的来源与时间，核对 ID 的宿主作用域和已有交接记录；使用确实可用的只读活动/写入证据入口做有限诊断。与此同时推进不依赖 A 且写入范围独立的已授权文档任务。未确认旧写入者及其在途操作停止前，不新派或接管 A 的文件范围。

**可声明：** “该 ID 当前不可查询，A 的当前执行/写入状态未知；依赖 A 的结果未取得。独立文档工作可以继续。”可将依赖范围记录为具体受阻，不能写 A 已终止、已关闭或已释放。

**依据与歧义：** 等待要求失效 ID 立即转有限诊断；生命周期要求旧 ID 失效时先确认旧写入者停止才重建执行者。not found 可能是 ID 作用域、生命周期或运行时问题，题设无法区分，也没有证明写入已经结束。

## 3. 到复核点但无可信进度，进度请求也无回应

**下一操作：** 保留 executing 标签、请求及无回应的事实，停止单纯顺延复核点的等待路径；题设已耗尽可用进一步诊断入口，应报告“无法取得可核实进展/状态、宿主无进一步诊断与自动唤醒保证”的具体缺口，保留待收取结果、旧写入风险和恢复所需证据，推进仍可独立进行的授权工作。若确无独立工作且无法继续有效诊断，则以该状态/能力阻碍交接，不承诺结束本轮后自动接续。

**可声明：** “宿主最后报告 executing，但活动与进展未核实，依赖结果尚未交付。”不能直接断言卡死、失败、停止或完成。

**依据与歧义：** 等待允许无进展依据时转有限诊断并报告缺口；收敛禁止无新依据重复；结束前的前台等待要求不应被解释为覆盖已触发的异常/无进展诊断。题设没给进度请求的非中断语义与合理响应窗口；实际请求前必须核实该语义。‘无回应’若只是刚发送而未给合理机会，不能立即断言请求失败；但也不能无限延长窗口。

## 4. 到复核点，有新的有效测试日志

**下一操作：** 在原记录登记新日志的路径、时间/内容依据、剩余工作和新的复核点，在原预算内继续有时限 wait；如存在独立工作可以同时推进。复核点应在需执行预算约束的时间之前，不能借更新复核点延长预算。

**可声明：** “已核实 A 仍在执行且测试有新进展，尚未完成；下次于记录的复核点复核。”不能把日志进度直接认作测试通过或阶段通过。

**依据与歧义：** 等待允许有可信进展后更新复核点。新的间隔取决于任务规模、日志所示剩余工作和剩余预算，题设不能推出固定分钟数。

## 5. ‘实现好了’，尚未核验文件

**下一操作：** 先读交付报告和实际文件，按阶段 R/V 核对范围、产物、指纹、自检与交接、剩余写入；满足交付条件后派独立 checker，再独立 reviewer，最后主会话 gate。缺失项先补齐或形成具体缺口，不跳过检查职责。

**可声明：** “已收到实现者完成声明，产物尚待核验；独立检查、审查及 gate 未完成。”实施者已交付并记录自检才满足正式‘待检查’条件，单句‘实现好了’不能证明该条件全部成立，更不能置检查通过/已验收。

**依据与歧义：** 状态、SKILL C.2–C.5、生命周期。题设没给自检记录，因此正式状态转换须核对；产物可读也不证明没有活动写入或已释放槽位。

## 6. 没有结束后自动唤醒，准备承诺十分钟后处理

**下一操作：** 将表述改为前台进度说明，随后实际调用有时限 wait，并按已定复核点查状态；等待结果到达就处理。只有持续保有前台执行、复核时间安排和预算支持，才可描述该前台复核安排。不能以“我继续等，十分钟后会主动处理”作为最终回复结束本轮。

**可声明：** “A 仍在执行，当前继续前台等待；宿主未保证本轮结束后的自动接续。”不能承诺已经退出后十分钟自动介入。

**依据与歧义：** 等待、适配。题设只保证前台工具，并无后台完成唤醒或定时唤醒。十分钟是否在既有预算内也未给出，不应自行加一个停止/介入期限。

## 7. 保证完成唤醒，但没有定时唤醒

**下一操作：** 核实题设保证覆盖当前 A、当前主会话及待收结果，保存 agent/background 标识、结果读取与恢复方式和下一动作后，可以让出本轮。完成通知唤醒时先读实际结果，再核验产物并接续后续检查。若当前还承担必须按时介入的预算或复核约束，保留前台执行该约束，或先取得真正的定时机制，不能用完成唤醒替代。

**可声明：** “后台任务 A 可追踪，宿主保证完成后唤醒本会话，届时读取并处理结果。”不能承诺十分钟后、超时后或无完成事件时主动介入，也不能保证任务将在某时完成。

**依据与歧义：** 等待明确分离完成唤醒和定时唤醒。题设足以支持完成事件驱动的让出，未给出其他定时职责；如现实任务已有预算截止要求，是否可让出还取决于该约束。

## 8. wait 仅表示邮箱更新，实际为进度通知

**下一操作：** 使用宿主实际的消息读取入口取得完整通知，按内容确认它是阶段进度；更新相关进展或缺口，仍保留完成结果待收取。若尚未到复核点，继续有时限 wait；已到点则核对可信进度后更新复核点或进入有限诊断。

**可声明：** “收到 A 的阶段进度消息，未收到完成报告。”不能把 wait 成功或邮箱更新写成工作完成。

**依据与歧义：** 等待、适配。题设未给进度内容质量与累计时间，不能认定任何进度通知都足以顺延复核点，也不能从通知推断当前仍在活动。

## 9. 普通消息请求高推理，代理文字称已切换

**下一操作：** 保留 send_input 回执与文字答复，查现有配置记录或宿主已提供的有效配置查询接口；有记录则据此判定，没有则记推理档位未验证。不能为补证据擅自重启写入代理、改模型或构造配置接口。

**可声明：** “高推理要求已成功发送，代理自述已切换；没有配置证据，实际档位未核实。”不能声明 high 已生效。

**依据与歧义：** 模型、适配明确普通文本不是配置操作，代理自述也不是宿主配置回执。题设未给 A 的原档位，不能反向断言当前一定不是 high。

## 10. 创建参数 high 且宿主确认，随后正常超时

**下一操作：** 复用创建参数与成功回执作为已验证配置证据，按等待规则继续有时限 wait；复核点到达才复核实际进度，不为正常超时重复配置或重启代理。

**可声明：** “A 创建时 high 配置已获宿主确认；没有已知配置变化。当前 wait 超时仅表示该次未收到完成结果。”不能将超时解释为降档、配置失效或模型能力失败。

**依据与歧义：** 模型允许创建参数加成功回执作配置证据；收敛与等待区分正常超时。实际复核点和预算未在本题给出，不能据此允许无限等待；该回执也不证明产物质量或所有后续 turn 的独立配置语义。

## 11. 连续工具错误，建议一直重试

**下一操作：** 拒绝把错误重分类为正常等待，保存原始错误、调用参数/ID/时间及影响；停止无依据的同动作重试，核对实际入口和可用状态查询。只有新证据、修复或明确暂态依据才允许该失败动作至多一次重试，再失败形成具体阻碍/交接并推进独立任务。

**可声明：** “等待接口异常，代理状态尚未取得，结果未验证。”不能声明 A 已失败、仍运行或产品实现失败；不能以此自动换模型/客户端。

**依据与歧义：** 收敛明确工具错误不享正常等待豁免。题设未给错误类型与既往重试次数；因此不能再自动追加一次重试，更不能断言根因是某模型。

## 12. 预算到期，A 仍写入，input 默认中断

**下一操作：** 停止追加实现任务并进入预算停止的安全交接。先核实是否有已支持的非中断消息方式；若有，发出“在最近安全边界停止、落盘当前结果和剩余项”的请求并核实停止。不得用默认会中断的 input 假装普通协作消息。若只能用 interrupt，须依据实际工具语义执行停止控制、保留现场并跟进在途操作/活动写入是否结束；不能将 interrupt 成功直接作为主会话接管同一文件的依据。完成安全停止后保存交接与未完成 R/V；预算已到期也不授权主会话接着实现。

**可声明：** “约定预算已到期，正在安全停止/交接；A 的写入结束尚未确认。”确认实际停止后可以声明预算停止及已保存内容，仍不能写任务完成、已关闭或槽位释放，除非各有对应证据。

**依据与歧义：** 等待、生命周期、共享协议“授权、决策与恢复”。题设缺非中断接口、interrupt 对子进程的效力及安全边界信息，无法给出虚构工具参数；最小安全收尾所需时间与是否允许继续到边界也未明确，不能借安全收尾无期限执行实现。‘立刻 interrupt 然后接管’同时缺停止证据与继续实现预算，不成立。

## 13. idle、无产物、无完成报告

**下一操作：** 立即转有限诊断：读取待处理实际消息与失败输出，核对原交付路径、ID/任务关联、最近交接及工具操作状态；必要时且已核实输入语义后索取一次具体结果/错误报告。缺口无法补齐则报告依赖受阻并继续独立项，不再 wait 十次。确认旧写入者和在途操作已停止后，才可在原授权内决定复用修复或重建执行者。

**可声明：** “宿主最近状态为 idle，但交付产物和报告缺失；结果未验证，需要诊断。”不能写工作完成、代理已关闭、槽位释放，也不能仅凭 idle 断定所有子操作停止。

**依据与歧义：** 等待明确 idle 且缺结果应立即有限诊断；生命周期区分工作状态与资源状态。产物路径错误、交付失败和消息未读取等可能性仍未区分，不能先指定根因。

## 演练结论与证据边界

以上是当前文本对 13 个模拟场景的应用结果。可从文本判断的动作分界包括：复核点前的正常超时继续等待；异常、失效 ID、idle 缺结果或复核后缺进度进入有限诊断；完成报告进入产物核验及后续职责；完成唤醒与定时唤醒分别举证；真实配置回执与自然语言要求分别记录。

尚未观察真实客户端/模型/插件版本、真实等待轨迹、turn 结束后的唤醒、定时能力、配置执行和在途写入停止。本演练没有进行前后版本行为比较，不构成真实 codex-glm 宿主验证，也不据此确认根因或修复有效。

## 补充演练：14. 后台继续运行、消息入队，但仅用户消息开启新 turn

**下一操作：** 不发送承诺自动处理的最终回复；保留前台执行，按既有复核点调用有时限 wait。结果到达后读取真实消息与产物，核验交付并进入后续已授权流程。若等待期间到复核点则查状态和可信进展，若出现错误或状态变化则按有限诊断处理；不能仅因为完成消息可入队就结束本轮。

**可声明：** “A 仍在执行；宿主保证结束本轮后 A 继续运行、完成消息入队，但不会因此自动开启主会话新 turn。当前继续前台等待。”不能声明后台自动接续已具备，也不能承诺结束后收到结果就主动处理。若因用户暂停、预算到期或具体能力阻碍确需结束，应保存交接并如实说明需要用户新消息才能恢复；题设中的前台等待可用本身不构成这个停止理由。

**依据与歧义：** 等待要求当前任务具备完成通知自动唤醒机制才可据此让出；适配明确“子代理继续运行或消息入队”不等于主会话自动恢复。本题已明确新 turn 只能由用户触发，因此自动唤醒能力不是未知而是不具备。单次 wait 时限、已有复核点与预算未给出，不能编造具体分钟数；这些参数不改变继续前台等待而非结束承诺的动作结论。

## 第 28 行增补对前 13 题的影响核对

新增句明确：按等待章节核实进展并更新复核点的“等待→状态复核→等待”，不算无进展调查周期。它不改变前 13 题的操作与状态结论。

- 第 4 题已有新的有效测试日志，原结论正是登记可信进展、更新复核点并继续等待；增补进一步排除了把这种合法循环误判为跨动作空转的读法。
- 第 1、6、10 题原已按正常前台等待推进；到点复核取得可信进展后，可以沿用增补说明继续等待。三次正常超时不变成停止条件。
- 第 3 题仍只有 executing 标签且无可信进展，不满足增补的“核实进展”前提，不能借该句无限顺延复核点。第 8 题仍须判断进度通知内容是否可信，通知存在本身不满足前提。
- 第 2、11、13 题仍是失效 ID、工具错误或 idle 缺结果，增补明确未扩大这些异常的豁免。
- 第 5、7、9、12 题分别涉及交付核验、唤醒能力、配置证据、预算与安全交接；增补未改变相应条件。
