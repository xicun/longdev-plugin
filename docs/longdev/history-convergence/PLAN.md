## 决策与安全回退

- 2026-09-23：两类归档分开：结束且无引用的可读任务记录进入docs/<kind>/archive/<task>/随Git持久且排除活动枚举；收掉旧入口时原始保护副本才进.work/longdev-migration/archive/。既有v013 docs位置与正常后续编辑不无依据重排。dry-run显示全部去向。

- 2026-09-23：用户追加dry-run，新增R08/V09，不替换原需求。--dry-run必须无锁/journal/目录/index写入；--check保留简短只读状态。
- Git跟踪校验采用index blob与当前持久文件一致，不自动add；首次迁移awaiting_tracking是可继续阶段gate/提交的待收尾状态，不以受阻exit造成提交前置死循环。阶段提交后重跑完成归档。
- 不新增复杂人工分类DSL：未知保留并给出依据，主会话按现有任务内容核对；归档只逐项处理归属明确文件。

- 2026-09-23：分类、引用闭包、迁移和归档共享事务状态，阶段1作为可独立验证的完整链条，不按文件数拆断；阶段2隔离安装/发布外部状态。
- 不可靠判断一律保留并报告：未知任务来源、矛盾状态、未解析引用、缺失证据、内容冲突均不自动归档。保守留下不等于完成收敛；报告区分已迁移、已归档、保留待核对、受阻。
- 先复制/校验、再核对 Git 跟踪、最后逐项归档；无 Git 或不能确认跟踪时保持旧记录并报告，绝不自动 init/add-force。保留未知兄弟内容，至多清理由本次迁移确认空的任务目录。
- 现有 `completed()` 遇 v0.13 marker 直接返回、旧测试要求忽略后续旧写入，这与新用户要求冲突：按 R05 明确升级协议及对应测试，保持 docs 正常编辑不被旧哈希覆盖。
- 跨机器必需证据不能仅依赖忽略的 .work；已有材料不足以产出可靠摘要/副本时显式保留阻碍，不伪造证据或自动宣称已验收。
- guard 是本插件角色受控写入前的真实检查入口，不宣称能拦截任意旧客户端或操作系统级写入；旧会话分叉由再次启动检测。
