## 1. 双槽多轮（R01–R04 / V01–V04）

## 2. 结果丢失（R02 / V02）

下一动作：核对缺失路径及 final 中的交付引用，向原代理索取或补回该结果与证据；保持本项待核查，不能关闭并宣称交接完成。对无关工作先核实授权、独立性和已知空位，确认不依赖缺失结果后可用该空位新建对应执行者；不能将旧代理改派后丢掉补交责任。

证据与容量：已有一空位；旧代理 final 不增加容量。接手者仍无法恢复原成果是明确缺口。依据 P132、P137–138；题设没有证明成果实际完成，结果不能记为通过。

## 3. 在途写入（R02 / V02）

下一动作：登记测试进程及共享结果仍在写入，要求在安全边界完成或依宿主真实接口停止该操作，再查询进程/操作终态并核对输出稳定。期间不关闭、不让新写入者接手同一范围。interrupt 只停模型生成，不能替代停止测试的证据。

证据与容量：需操作结束回执和无活动写入的事实；目前关闭条件未满足，容量未释放。依据 P131、P138、S。若无查询/停止能力，明确受阻对象并推进不依赖该共享结果的已授权工作。

## 4. 近期返工（R01、R02 / V01、V02）

下一动作：保留实现代理，记录“等待正在执行的 review；返回失败则返工、返回通过则复核是否关闭”。继续独立 review 与主会话可做的工作，不机械重新 spawn 实现者。

证据与容量：已有实现交接，review 的真实执行状态及其返回是可观察复核点；实现者 idle 仍占槽。依据 P133、P137、P139–140。返工是否需要尚未确定，不将等待记为任务完成。

## 5. 暂留到期（R02、R04 / V02、V04）

下一动作：review/gate 返回后核查暂留理由已消失，检查该实现代理及其操作已结束且无写入，关闭并登记实际回执。

证据与容量：题设给出的 review 通过与 gate 完成消除了本次保留目的，但没有直接提供“无活动操作”或“关闭释放”的证据；前者先核实，后者只依回执更新。依据 P135、P138–139，不无限延期等“可能有下一次”。

## 6. 同职责复查（R01、R04 / V01、V04）

下一动作：核对原 reviewer 的身份、任务链、权限、最新修复文件和验收项，向其 idle 线程 followup 独立复查。传入新产物/失效证据，不能直接复用旧通过结论。

证据与容量：原 reviewer 未参与实现且宿主明确支持 followup，具备匹配复用依据；followup 不创建新线程，开放数不变。依据 P137、P141、S。若当前权限不再匹配，先修正授权/交接而非凭角色名称复用。

## 7. 跨职责独立性（R01、R03 / V01、V03）

下一动作：拒绝将实现者改名为 reviewer；先核实实现成果/证据/交接、无活动操作和无明确后续，再安全回收可关闭者。只有确认容量后才新建未参与实现的 reviewer。若实现者有明确返工后续，权衡从完整交接重建实现者，不以腾槽为由丢失状态。

证据与容量：目前满额，idle 不释放。关闭/释放能力未给定，不能假设成功；若不能回收且无匹配独立者，审查保持待检查，主会话只继续其他已授权独立工作。依据 P137–140。不会让参与实现的主会话换帽子来填补独立性缺口。

## 8. 关闭失败（R03 / V03）

下一动作：记录失败请求、回执和尚未释放状态，停止没有新依据的 close/list/spawn 重试。明确恢复条件为宿主提供有效状态变化、关闭修复或容量证据，继续主会话能独立完成的工作；必需独立审查保留待检查。

证据与容量：已收到 definite failure 和既有 limit reached，没有运行中工作可等待，也没有释放证据；不能建立轮询等待假进展。依据 P134、P140、S。未确定的是宿主故障原因，不靠循环请求猜测恢复。

## 9. 只有中断工具（R03、R05 / V03、V05）

下一动作：在交接完整且无在途操作后，将闲置代理记录为关闭能力缺失、资源未释放/无法核实。不能把 interrupt 当 close，不编造关闭命令，不使用 kill 或删除记录替代。新职责不匹配，因此不复用该 ID；先核对真实可用容量。

证据与容量：题设只说明工具集合，没有说明容量已经满；若查询证明确有空位且新工作独立，可以正常新建。若容量不足或未知，按限制继续主会话可做工作，不等不存在的在途工作、不无据反复 spawn。依据 P137、P140–141、S。此处不能从“无 close”推断“必然无任何空位”。

## 10. 异步关闭（R02、R03、R05 / V02、V03、V05）

下一动作：保存 operation ID 并保持关闭待确认，通过题设状态接口跟踪原操作；第一次 pending 后不重新提交 close，不立即密集查询。按接口给出的轮询/通知契约设置有限后续检查；若该契约、终止时间或恢复办法未知，先核实具体接口限制，再决定检查安排。

证据与容量：pending 尚未确认关闭或释放，不能新增同范围写入者或计出可用槽。允许等待真实在途关闭操作，不能把“有 operation ID”变成无限等待许可。依据 P134、P138、P140、S。题设未给最终回执，结果保持待确认。

## 11. 关闭不等于容量遥测（R03、R05 / V03、V05）

下一动作：将线程记为已关闭，将资源释放/可用容量记为未知；查询宿主实际支持的容量状态或接口说明。如果没有可验证入口，就报告该能力缺口，不能在台账中自动加一可用槽。

证据与容量：closed 回执只证明线程关闭。题设没有给后续 spawn 或容量探测的契约，本演练不假定可创建新线程，也不把一次成功关闭当作整个生命周期实测通过。依据 P135、P140、S。可继续主会话独立工作，无新状态不重复探测。

## 12. 失效 resume（R02、R04 / V02、V04）

下一动作：用现有交接定位旧任务与写入范围，定向核实旧代理和它启动的操作是否已停止。not found 只说明该恢复调用没有找到 ID；不能直接新建同范围写入者。确认停止后才从交接重建必要执行者；未能确认时保持交接就绪、写入待接管，推进无冲突的只读或独立工作。

证据与容量：交接完整是必要条件，但不是停止/释放证据。当前旧线程存在性、活动工具和容量均未知。依据 P138、P141、运行时写入租约/切换状态机。不能凭旧 ID 无效清掉旧任务语义。

## 13. 恢复后漂移（R04 / V04）

下一动作：先重读当前规则、任务、授权和验收项，再比较当前文件与旧测试覆盖；旧 commit 的通过只作为历史证据。限定恢复代理的新写入范围，对受改动影响的验证重新执行，未受影响且可对应当前产物的证据才复用。

证据与容量：resume 成功未证明旧授权仍适用，不能让代理继续按旧摘要写入。实际作用是复用或新建还要看宿主契约，不能仅凭名称推断容量变化。依据 P141、S 及会话交接契约。当前差异具体内容未给定，不能预先报重新验证通过。

## 14. 旧任务兼容（R04 / V04）

下一动作：保持旧 PLAN 的 R/V、阶段状态及证据不变，在既有交接记录只补可核实的当前线程信息和“任务归属未知”。定向查宿主元数据/既有交接用于归属判断，不为填表追建猜测的历史代理表，不关闭可能属于其他任务的线程。

证据与容量：可查询线程并不等于知道任务所有权或已释放；无法识别时保留未知，按实际容量与写入冲突决定新工作。依据 P127、P140–141。缺少代理登记本身不使旧任务无效或重开已完成阶段。

## 15. 同项目不同任务（R01、R02、R04 / V01、V02、V04）

下一动作：先把 X 的未完成项、授权、写入范围与交接保留在 X；核实其 idle 是否仍伴随工具写入。Y 是无关任务，使用自己的任务记录和新执行者，不能仅因同仓库同角色就 followup X 的代理去执行 Y。

证据与容量：需核对 X/Y 文件范围和依赖；Y 真正独立且容量可用才可推进。若同范围写入存在冲突，先完成 X 的安全交接/停止条件，不擅自取消 X 腾槽。依据 P137–141。题设没有提供容量或无冲突证据，因此这里不宣称 Y 已可派发。

## 16. autopilot 迭代结束（R01、R02、R04、R05 / V01、V02、V04、V05）

下一动作：盘点产品层 PO、acceptance 和本迭代全部任务级代理。逐一接收并核对结果、证据、剩余项，核实无在途操作；题设没有给 PO/acceptance 明确下一动作，不以“产品还有下一轮”为理由自动暂留，满足安全条件后关闭并跟踪实际回执。任务级交接完成也仍需检查活动写入。

证据与容量：只有宿主确认释放才计容量增加。产品 backlog 与下一轮授权继续有效，不因代理关闭把产品标完成。若收尾时确实安排了同职责下一动作及可观察复核点，可以据新事实登记暂留并匹配复用；当前题设尚未提供这一事实。下一轮 acceptance 仍须独立于其验收对象的实现。依据 A36、P137–141、S。
