# autopilot

开工读 `../../.claude-plugin/plugin.json` 的 version，报告 `longdev vX.Y.Z (autopilot)`。先读 `../longdev/SKILL.md` 和 `../longdev/references/execution-protocol.md`（路径相对本文件）：迭代内状态、证据、基线和审查沿用 longdev；本文件负责产品层循环。

盘点产品记录前，执行 longdev 的启动迁移命令，脚本相对本文件为 `../longdev/scripts/migrate_workspace.py`，`--project` 指向当前项目根。`status`/讨论只加 `--check` 探测；迁移受阻先处理，旧目录仅作保护副本，不作为第二个产品入口。

**宪章记录用户意图与授权，不能替代或限制用户后续明确指示。** 在已有授权内自主推进；关键目标、范围或授权缺失时才澄清。建议、默认值和用户沉默均不是授权。

## 落盘与职责

产品目录 `docs/autopilot/<产品名>/`；第 N 轮任务目录 `docs/longdev/<产品名>-i<N>/`。

| 文件 | 写入者 | 内容 |
|---|---|---|
| `CHARTER.md` | PO 起草，主会话依据用户决定确认或修订 | 稳定编号的目标、非目标、V 验收全集、预算、授权来源；变更记录 |
| `BACKLOG.md` | product-owner | 引用目标/V ID 的候选、依赖、状态、证据指针；独立观察区 |
| `iterations/<N>.md` | PO 写入场；主会话写收尾 | 本轮目标、选题、需求与阶段对应、有效宪章版本、检查结果和恢复入口 |
| `acceptance/<N>.md`、`acceptance/final.md` | acceptance | V 全集逐条结果、产物状态、原始证据、限制和验收授权 |
| `design/<功能ID>.md` | PO | 已选功能的设计参考与边界，不扩范围 |
| `scout-repo.md` | scout | 已有项目现状；绿地项目可省略 |

模板在本 skill 的 `references/`。索引宜精简，细节外置并保留指针，不能为行数删除需求或证据。
新增角色 `longdev-product-owner`、`longdev-acceptance` 继承主会话模型。迭代内按 longdev 派活。主会话通常读摘要；覆盖核对、冲突、恢复或诊断所需时读取原文与日志，文件变化后可重读。

## 第一步：恢复与状态

先盘点产品目录，读取有效宪章、最新迭代和验收索引，核对实际产物、证据有效性和 longdev 状态；不能只凭标题、勾选数或“收尾”小节存在就跳过步骤。

- 没有产品记录：进入 A。
- 只有草稿：复用已回答问题和已有授权，补足尚未解决的关键项。
- 迭代未完成：从最早未完成或证据失效的步骤续接；实现完成不等于检查或验收完成。
- 实施已完成但报告缺失：补检查或报告，不重做已验证实现。
- 目标达成、预算停止或受阻后用户要求继续：依据新指示更新预算、目标或解除条件及影响记录；不重复完整问卷。
- 多个候选且上下文无法唯一确定：问用户选择。`status` 只报告状态、证据和剩余项，不实施。

## A. 建立宪章

1. 创建产品目录。已有代码派 scout 调研，记录用户现存改动及约束。
2. 派 PO 起草：给用户原话、已有决定与授权、scout、`references/charter-template.md`、`references/charter-interview.md`。用户已经明确的维度直接记录，不重复问卷。
3. 只澄清会改变目标、重要范围、验收、预算或授权的问题。可用 AskUserQuestion 减轻输入负担；工具不可用时简短集中提问。常规实现细节可作为标明的假设；未决授权不可按推荐默认，关键缺口不得因问卷批次上限被跳过。
4. 展示可审阅草稿与待决项。已有明确方案和实施授权且无关键缺口时记录来源后继续；否则只请求缺失的必要决定。已同意的部分不再确认。
5. 转正为 `CHARTER.md`，记录版本和确认依据。宪章不得被 agent 为通过验收而自行放宽；后续用户明确变更，由主会话记录原话/日期、变更条款、受影响需求/阶段/证据并更新，再继续独立且已授权工作。

## B. 第 N 轮

1. 派 PO 规划：读有效宪章、backlog、上一轮收尾和验收；把未达成 V 转为范围内候选，观察不自动转功能。按贡献与依赖选题，遵守每轮上限。必要时为已选功能做设计调研，写入场，附目标/V ID 和设计指针。候选低于阈值只能成为停止原因，不能推导目标达成。
2. 按 longdev 执行完整立项、阶段实现、review、gate 和整体审查。交给 planner 的输入包括本轮可观察目标、有效宪章及 V 全集、选中功能、依赖和设计参考，不把一句话当成全部需求。

   产品 V 全集用于每轮产品报告；本轮 longdev 必需 V 是选中目标及必要回归的明确子集，任务内技术 V 另设映射。未选中的后续功能不阻塞本轮阶段通过，但仍留在产品报告中，不得消失或被标成不适用。主会话记录本轮子集及选择依据，不能事后缩小集合掩盖失败。

   | 需要处理的分支 | 自主模式处理 |
   |---|---|
   | 计划待确认 | 已授权 acceptance 代理计划核对；否则沿用用户已确认方案，仅对新增关键取舍请求决定 |
   | 技术取舍 | decider 在目标与事实支持且已授权范围内决定；不能用“可逆最小”替代缺失的关键用户意图 |
   | 不可逆或外部动作 | 核对既有授权对象、范围和条件；有效即执行并验证，缺失则阻塞该动作并推进独立工作 |
   | 代理决策累计 | 定期汇总并复核相互影响；数量本身不取消已有授权，也不让未决关键项无限累积 |
   | 阶段过大 | 按耦合、风险及可独立验证性调整拆分，保留需求对应 |
   | 两轮修复仍失败 | 分类原因和依赖；无新证据不重复尝试，按下节隔离或记录受阻 |
   | agent 不可用 | 如实记录工具限制，选择可满足同等检查的执行方式；达不到则保持未验证，不制造通过 |

3. 修复或隔离前，记录失败原因、已有尝试、新证据和受影响依赖。自动撤回只限用户已授权、归属明确且可恢复的本任务改动，优先可审阅编辑；不得使用宽泛 Git 恢复或覆盖用户改动。核对目标行为恢复、相关回归、原有改动保留及前序残留；`git diff` 为空不是撤回充分证据。隔离失败功能及依赖阶段，只继续前提仍成立的阶段。前序已实现代码逐项决定保留、禁用或授权撤回，不能盲留给最终审查。
4. 迭代整体检查通过后派 acceptance，给有效宪章版本、验收授权、当前产物状态及 `acceptance/<N>.md`。存在隔离项时，明确列出独立可交付子集，对该子集执行整体审查和 gate；隔离项及依赖继续保留失败/受阻与全部 R/V，报告不能称整个迭代检查通过。子集可交付或本轮受阻需报告时仍进入 acceptance，无法运行的项目如实标未验证。从用户路径取得独立证据，逐条报告产品 V 全集；未完成项不能省略。
5. **迭代 gate**：主会话按公共协议核对预期 V ID 全集与报告一一对应，检查漏项、重复、未知 ID、证据路径、期望/实际和版本时效。机器命令需真实退出码和完整日志，但退出码为零不等于需求达成。核验报告所支持的结论和授权，必要时针对性复跑；无变化不重复整套验证。只有完整覆盖且每项有效通过，或有已确认依据的不适用项，才能判定全绿；未验证/过期证据不能通过，不适用不得自行豁免必需验收。
6. 收尾落盘：记录检查与代理验收的不同结论、V 结果统计、证据指针、隔离依赖、剩余工作和下一入口。每个 longdev 阶段已按共享协议默认本地提交；本轮新增产品层记录、acceptance 和 backlog 在迭代 gate 后形成限定范围的收尾提交。保护既有 staged 和同文件他人修改；失败/无法安全分离记录提交受阻，不能静默积压到下一轮。用户明确禁止提交等例外沿用共享协议，不把默认本地提交推导为自动 push。
7. 判定下一步：有效 V 全集通过且总体目标达成，进入 C；预算用尽或候选耗尽但仍有未达成项，进入 C 的“预算停止/候选耗尽”报告；系统性失败、缺失关键授权或外部依赖阻塞则记录“受阻”及解除条件，继续独立部分后进入 C 报告。其余继续 N+1。两轮修复或隔离比例等仅作重新诊断触发器，不能冒充成功。
8. 向用户简报实际进展与证据。接续从文件与实际状态恢复，不宣称恢复零成本。

## C. 最终报告与停止

1. 派 acceptance 写 `acceptance/final.md`：有效 V 全集、总体目标、当前产物状态、有效证据、全部隔离/推迟及依赖、待复核决定、观察和剩余限制。先核查证据是否覆盖最终产物；有影响改动或缺口才补必要验证。
2. 主会话确认报告存在、覆盖完整、原始证据可追溯且结论一致后，才记录最终状态：**目标达成 / 预算停止 / 候选耗尽 / 受阻**。报告缺失或未核实只能记“待最终检查/待报告”，不得标已收官或成功。
3. 展示报告，明确自检、代理验收授权与用户验收的区别。用户未授权代理验收时保持待用户验收；有明确授权时记录其来源和适用标准，不能把代理结论冒充用户亲自验收。停止原因、未达成项与后续恢复条件须如实呈现。

## 授权与边界

- 既有明确授权在其范围内持续有效；发布、push、部署、外部发送等按用户授权执行，未授权不得执行。工具/平台上位限制仍适用。宪章不得自行授予用户未给予的权限。
- 目标和非目标以用户指示为准，未列功能不自动进入范围；默认值和观察区不是新需求。
- 🚫 不静默重试；解除需新证据或用户变更，并核对依赖和预算，不能改状态掩盖历史失败。
- 保留任务审计记录。原始日志/备份在项目 `.work/`，可跨机器复核的摘要、manifest、授权及剩余事项在 `docs/` 随阶段提交；原始证据缺失须补查，不能冒充仍有效。错误不丢弃，不因格式计数或统计不一致指控造假，先查版本、环境和选择条件。
