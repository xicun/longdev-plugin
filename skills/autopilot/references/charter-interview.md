# 宪章问卷

先核对用户原话、历史明确决定、项目事实和既有授权，只问答案会改变关键目标、范围、验收、预算或授权的问题。已明确的内容直接落定并注明来源；完整方案已获实施授权时不重复问卷或整篇确认。

## 六个检查维度

| 维度 | 需要澄清时的内容 |
|---|---|
| 用户 | 谁在什么场景使用；不能从原话推断时问 |
| 形态与平台 | CLI / Web / 桌面 / 库及运行环境，优先现有项目事实 |
| 范围 | 已授权核心场景、非目标和未决边界；同类产品仅供参考，不自动成为用户需求 |
| 质量 | 与风险匹配的行为、边界、失败路径及验证要求；低影响可逆改动不机械新增测试 |
| 预算与停止 | 有限迭代预算、每轮上限、停止和恢复条件；无预算授权不能默认无限运行 |
| 授权 | 代理计划确认/验收的范围与标准，以及确需执行的提交、部署等动作；先核查已有授权 |

## 提问与落定

- PO 每题说明“答案决定哪个条款”。说不出影响就不问。常规实现细节在已授权范围内自行决定并记录必要假设。
- AskUserQuestion 可用时每批遵守工具题数/选项上限，推荐项列首并说明影响；范围题可多选。Other 与 notes 原话保留，不替用户改意图。
- 授权题只用于真实缺口，不为已授权工作重复设关；工具不支持必要提问时集中用简短自然语言问。
- 优先一批解决，通常不超过两批；这是交互负担目标，不能把未决授权或关键范围按推荐默认。用户未回答不构成许可。
- 用户未选择的功能只有在明确说明选项含义且与既有目标不冲突时才记为本轮非目标；未列出的功能也不自动入范围。主流调研遗漏不是扩张理由。
- 已知决定标“用户原话/既有授权/问卷”，常规假设标“实现假设”；新外部影响或代理验收授权必须写明来源、对象、范围、条件。
- 展示草稿和尚待决定事项。已有明确授权且无关键缺口时记录依据转正；否则只请求必要决定。后续用户明确变更优先于旧宪章，记录版本及受影响条款、依赖和证据。
