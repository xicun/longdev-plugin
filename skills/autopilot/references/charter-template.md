# CHARTER.md 模板（宪章）

product-owner 立宪时按此结构写 `<产品目录>/CHARTER.draft.md`，问卷 + 用户确认后由主会话改名 `CHARTER.md` 并**冻结**。

宪章是自主循环里**唯一代表用户的文本**：迭代中所有「问用户」都变成「问宪章」，所以每一节都要写到「一个没有任何 context 的 agent 拿它就能做判断」的程度。写不进宪章的偏好，循环里就不存在。

**硬上限 80 行。** 每个条款带编号（U/F/G/N/V/Q/B/A + 数字），backlog 的「宪章依据」、decider 的裁决依据、acceptance 的核对都靠编号引用。

```markdown
# <产品名> 宪章

**产品一句话**：<给谁、解决什么问题、长什么样。收官时逐字验这一句。>
**创建于**：<YYYY-MM-DD>　**确认于**：<YYYY-MM-DD>
<!-- 收官时主会话在此下方加 **状态：已收官（日期）**。其余任何时刻任何 agent 不改本文件。 -->

## 目标用户
- **U1**：<画像一句话：谁、在什么场景、多懂技术>（问卷）

## 形态与平台
- **F1**：<CLI / Web / 桌面 / 库；运行环境和启动方式>（问卷）

## 核心场景
<!-- ≤5 条，每条可观察（用户做什么 → 得到什么）。G 编号是 backlog「宪章依据」的主要引用对象。 -->
- **G1**：<...>（问卷）
- **G2**：<...>（目标原话）

## 非目标
<!-- 防发散的主闸。范围题没勾的全部落这里，加上调研见过但用户没要的主流项。宁多勿少。 -->
- **N1**：不做 <...>（问卷）
- **N2**：不做 <...>（默认）

## 验收清单
### 机器可判
<!-- 每条一行：`命令` → 期望。迭代 gate 逐条跑真实退出码，所以立宪时就必须可执行——哪怕第一版只有「构建通过」「测试套件通过」兜底，随核心场景写细。 -->
- **V1**：`<确切命令>` → exit=0
### 人工观察
<!-- acceptance 每轮从 U1 视角逐条核。写成可判定的行为，不写「体验好」这类空词。 -->
- **V10**：<做 X 能看到 Y>

## 质量约定
- **Q1**：<测试框架、目录、严格度档位；「不引入测试」也要显式写>（问卷）

## 预算与停机
- **B1**：最多 <N> 轮迭代，每轮 ≤<M> 个功能（问卷）
- **B2**：候选分阈值 <分>/5——某轮全部候选低于它即收官

## 授权边界
<!-- 只列问卷勾选的。没写的 = 不允许。push / 对外发布 / 删项目外文件永不出现——用户也授权不了。 -->
- **A1**：允许本地 git commit，每轮收尾一次（问卷）
- **A2**：允许安装项目内依赖（问卷）

## 主流参考
<!-- 调研结论每条一行，是范围题选项的出处。不粘调研正文。 -->
- <同类产品 X 的主流形态是 ...>
```

## 填写纪律

- 每条必须带编号——引用不出编号的条款等于没写。
- 每条标出处：（目标原话）/（问卷）/（默认）。收官复盘时要能分清哪些是用户拍的、哪些是推荐落定的。
- 相对日期一律换绝对日期。
- **「非目标」是宪章里最值钱的一节**：发散从来不是从目标里长出来的，是从没写下来的非目标里长出来的。范围题里用户没勾的、调研见过但用户没提的，都显式写进来。
- 「机器可判」的命令写确切原文，不写「跑测试」这种要人翻译的话——gate 是照抄执行的。
