# iterations/N.md 模板

上限 40 行。「入场」由 product-owner 规划轮写；「收尾」由主会话追加（≤12 行，只放机器数字和指针）。下一轮 PO 的输入就是这份 + `acceptance/<N>.md`，所以收尾的每个指针都要指得到。

```markdown
# 迭代 N

## 入场
**本轮目标**：<一句话，可观察结果。原样作为本轮 longdev 立项的"用户目标原话"，所以不要写成功能名罗列。>
**选中**：F2（G2，4 分，<理由半句>）；F5（减法，N2，<理由半句>）
**落选**：F3（2 分 < B2 阈值）
**上轮遗留**：<acceptance/N-1 未达成项怎么安排；N=1 或无则写「无」>

## 收尾
**longdev 任务**：`.claude/longdev/<产品名>-i<N>/`（final review 通过 / 经 <k> 轮收尾修复）
**迭代 gate**：V1 exit=0；V2 exit=0 <逐条原样，不改写成「全过」>
**验收**：<x>/<y> 达成（`acceptance/<N>.md`）
**隔离**：无 / F4（阶段 3 两轮修复未过，已回滚，`git diff --stat <SNAP>` 为空）
**决策备案**：本轮 +<n> 条（累计 <m> 条收官待复核）
**给下轮**：<一行；无则「无」>
```

## 纪律

- 收尾只放机器数字和指针，语义内容都在 `acceptance/<N>.md` 和迭代任务目录的 `reviews/` 里——PO 下轮读的是本文件和验收报告，**不要让它去读 review 正文**。
- gate 退出码逐条原样列，不许汇总成一句「验证通过」——这几行是收官报告里用户回溯每一轮的原始证据。
- 「本轮目标」写坏了整轮都会歪：它是 planner 拿到的唯一目标描述。写「用户能 X」，不写「实现 F2、F5」。
