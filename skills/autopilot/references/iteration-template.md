# iterations/N.md 模板

PO 写入场；主会话在检查和验收记录核对后写收尾。保持索引简洁，保留必要证据和剩余项，不能用“收尾存在”推断通过。

```markdown
# 迭代 N
## 入场
**宪章版本/依据**：<版本、用户授权指针>
**本轮目标**：<可观察结果>
**选中/落选**：<功能 ID、G/V ID、分与理由>
**需求与阶段**：<功能/V ID → 迭代任务需求/阶段；依赖>
**设计参考**：<文件路径或无；研究限制>
**上轮遗留**：<失败/未验证/隔离项及安排>

## 收尾
**迭代状态/任务**：<待检查/检查通过/受阻等；longdev PLAN 路径>
**产物状态**：<相关文件指纹、基线及未跟踪文件清单指针>
**V 全集核对**：<预期 ID；漏项/重复/未知 ID 均为零，核对记录路径>
**结果**：<通过 x / 失败 y / 未验证 z / 不适用 n；不适用依据>
**证据**：<逐项报告、原始日志、命令退出码与期望/实际指针>
**验收**：<自检/已授权代理验收/待用户验收；授权来源及结论>
**隔离及依赖**：<范围、原因、前序残留处理、相关验证及恢复条件>
**决策/剩余**：<待复核、未完成项及路径>
**停止/下一入口**：<继续步骤或目标达成/预算停止/候选耗尽/受阻；恢复条件>
```

报告遵守 `../../longdev/references/execution-protocol.md`。收尾引用有效的 V 全集和原始证据；正文摘要不能替代覆盖核对。最终报告缺失时不得写产品收官。本轮目标与全部映射共同交给 planner，不能只传一句话丢失约束。
