# Bug Reports

目标是把每项反馈的去向、历史尝试和当前证据保留到项目，支持跨会话调查。项目事实源是 `docs/bugs/reports.json`，`index.json` 仅派生；工具按编号读取，不常规把整个档案灌入上下文。原始大日志放 `.work/bugs/`，可携带验证摘要放 `docs/bugs/evidence/`。遵循项目忽略与敏感信息规则，不录入密钥。

## 触发与范围

Issue 是事项总称，Bug 是实际行为违反已约定预期的缺陷。类型与处理状态分开：预期依据不足先分流待澄清或保持 triage，有证据后再分类；不能靠改名取消未解决事项。环境/外部依赖可能是缺陷成因，不能仅凭外部错误就排除产品责任。本技能统一收集反馈并将需求转既有记录，不建立全量 Issue 管理平台。

- 新反馈：登记原话及逐项反馈，检索历史后分别关联 Bug、新建 Bug、转需求或待澄清。一般咨询不强行建缺陷。
- 修复后再次反馈：即使换措辞也先找旧问题，疑似关联即可启动复查；不要求用户重复编号或证明复发。
- 开工/恢复：读取 status、检索相关问题，按 BUG/FB 编号读取原始反馈和历史，核对实际代码/运行版本。旧记录不是修复授权，不接手无关旧问题。
- 准备交付：对照本轮原始反馈逐项核对去向，再检查关联问题的调查和验证。仅检查本轮承诺范围，不让无关历史问题阻塞交付。

## 执行

1. 定位本技能实际安装路径，运行 `python <技能路径>/scripts/bug_reports.py --project <项目绝对根> status`。首次无档案才 init；损坏/锁冲突应诊断，不重建覆盖。完整命令与 JSON 格式见 [CLI 契约](references/cli.md)。脚本不可用时明确报告并先保留原始反馈及未分流项，不静默跳过。
2. `feedback` 保存用户原文、来源及原文片段组成的条目。AI 逐句复核是否包含全部事项；CLI 不能证明拆分没有遗漏。原话不可由摘要替代。后续补充用新批次，不能重写原批次。
3. 用目标、条件、实际现象、验收标准检索 `search`（包含 closed 和 merged）。关键词不命中时换关键词并查看候选索引；输出只是候选，不能当语义去重结论。按 ID 阅读候选及其关联反馈，说明关联依据；同现象不同根因可独立建号并 relate，疑似先关联，不强行合并。合并保留旧编号和历史；拆分先 create 子问题，再 relate kind=split，并逐条调整反馈去向。
4. 保存当前事实、假设、下一步及关闭条件，历史修复用 repair 追加版本、原因、覆盖。每个有效调查结论及时落盘，不等会话结束。反馈路由到已有修复且该反馈登记于修复之后的问题，会按 FIX 编号触发一次复发，清除当前验证并重新调查；同一轮重复表述不重复计数。
5. 复发时 examine 原始反馈、旧修复与旧验证；用 investigate 记录旧判断支持与反证、实际运行版本、遗漏入口/条件、上次漏检原因、判别实验及实际结果。还未执行的实验如实写待执行，保持调查中；字段齐全不能代表根因已证实。不能只扩大补丁或重复“彻底检查”。
6. 对用户实际操作路径执行修复前失败/修复后通过的验证，检查此前相关场景。区分已有用例漏跑、覆盖不足或缺少用例，优先复用或补充能捕获该 Bug 的回归验证；用 quality_refs 关联已有需求、验收项、测试用例和测试运行，不另建测试平台。无法复现、局部测试或运行版本未核实时，保留缺口，不进入待验收。修复完成用 repair 登记，verify 绑定当前 FIX、版本、产物与证据哈希；复发后不得沿用旧轮结论。
7. 运行本轮 `check --feedback FB-... --bug BUG-... --delivery`。如果本轮仅做分流/调查，不宣称修复完成，运行不带 --delivery 的覆盖检查并逐项报告仍待调查的内容。自动检查只保证引用/记录/哈希一致；AI 仍须核对原文完整性、实际证据与授权。
8. verify 通过仅为 acceptance（待验收）；用户明确接受或有明确范围与标准的自动验收授权后才 accept。长程任务 PLAN/交接只引用 BUG/FB ID、本轮承诺及执行状态，不复制根因事实。简短汇报结果、证据与剩余项。

## 恢复与限制

每次写入使用最新 revision，冲突后重读相关档案再合并判断，不自动重放旧写。持久 JSON 是唯一事实源；reindex 可随时重建，索引 revision 落后时不得据它宣布当前状态。search 分页，show 单条 issue 或反馈批次，status 只摘要；问题历史较长时应定向读取必要字段，不加载全库。

普通项目由单文件原子事务降低历史丢失风险，适用于小中规模档案；不提供多机实时数据库同步、语义搜索服务或强制执行器。Git 冲突应依据两边原始记录合并，不任取一边覆盖。路径防护拒绝项目外引用、链接/reparse；写锁只协调本工具，不能阻止外部编辑，写前仍校验原始字节。

日志不一定跨机器存在。交付所需证据应提供可携带摘要（方法、输入/产物指纹、期望、实际、退出码、限制），原始证据缺失必须报告，不能以字段存在代替实际验证。规则触发与检查命令降低遗漏风险，不能承诺绝不遗漏。
