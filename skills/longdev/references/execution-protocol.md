# longdev / autopilot 共享执行协议

本文件是两个 skill、规划/实现/审查/验收角色共同使用的接口。主会话派发时提供本文件的绝对路径。具体任务的需求、授权与验证方法以任务记录及用户当前有效指示为准。

## 核心目标连续性

- 任务记录始终保留当前目标、范围、完成标准、已完成项、下一步和阻碍。新问题默认是当前任务的插入、澄清或状态询问，不自动替换目标。
- 回答插入问题后继续原任务；只有用户明确取消、暂停、改目标，或新指示与原目标不可兼容时才切换，并记录切换依据。
- 每次暂停、恢复或准备结束时，核对目标、R/V 集合、未完成项、失效证据、受阻事项和验收状态。解释过程、耗时或工具限制不能替代交付结论。
- 最终汇报前必须同步任务索引、状态表和验证记录，并检查没有过时或相互矛盾的文字；仍待验收、部分交付、受阻或长期效果待观察时，保留对应状态，不能写成整体完成。
- 会话可以被压缩、停止、恢复或替换。跨会话时以任务目录中的交接包和实际产物为准，不以聊天历史或客户端的 resume 成功作为状态证据。
- 交接包至少记录当前阶段、R/V、实际改动、有效/失效证据、阻碍、授权边界和唯一下一步。交接包写入并校验后，才允许停止旧会话或启动新的写入者。

## 需求与验证契约

- 每项需求分配稳定 `R01` 等 ID，记录内容、来源、边界、交付物、依赖、状态、证据与剩余事项。拆阶段不重编号；取消/替换记录用户依据，禁止静默删除。
- 每个验收项分配稳定 `V01` 等 ID，映射一项或多项 R、实施阶段、方法/命令、环境与期望结果。建立预期 V ID 全集后，逐项核对实际结果；零失败数或零未勾选项不能证明完整。
- 验证结果仅用：通过、失败、未验证、不适用。不适用需具体理由及适用授权/标准依据；必需项不能靠改写为不适用绕过，取消或降低需求遵守授权规则。
- 追加需求同步更新 R/V 集合；已确认的验收入口与实际执行记录分开。入口可依新事实调整，但须保留变更日期、理由、授权来源及影响的 R/V，不能追改标准使已有实现通过。

## 状态与责任

| 状态 | 必要条件 / 写入者 |
|---|---|
| 待执行 | 需求/阶段已登记，尚未启动 |
| 执行中 | 主会话确认依赖与授权满足；implementer 正在实施 |
| 待检查 | implementer 交付并记录自检；修复后也返回此状态 |
| 检查通过 | 主会话核实独立 review 与 gate 均通过，必需 V 证据有效 |
| 待验收 | 本轮/整体检查通过，已提交成果但尚未取得验收结论 |
| 已验收 | 用户明确接受，或指定验收者在有效自动验收授权内通过；写明来源 |
| 受阻 | 写明阻碍、影响 R/V、解除条件与仍可推进的工作 |

阶段检查通过后可以推进依赖满足的已授权工作，不必逐阶段请求用户验收。实施者不能写检查通过/已验收；审查报告本身不能替代主会话 gate。历史 `✅` 不是证据。恢复时检查 review、gate、V 集合及产物状态；任何受影响验证过期或缺项，都回到待检查或受阻。受阻解除后回到实际待完成的环节。

## 基线、改动归属与产物指纹

任务起点与每阶段起点记录于项目 `.work/longdev/<任务>/baselines/<标识>/`（autopilot 产品层使用 `.work/autopilot/<产品>/`）：

1. 仓库根路径、时间、HEAD（无提交/非 Git 如实记录）、`git status --porcelain=v1 -uall`。
2. 已暂存和未暂存差异分别保存为 `git diff --cached --binary` 与 `git diff --binary` 的补丁；列明已经存在的用户/其他执行者改动。
3. 未跟踪文件逐个登记路径、内容哈希；可能要改动的既有未跟踪文件保存内容副本。纳入任务的被忽略文件、嵌套仓库/submodule 单独登记状态及必要副本，不能用父仓库 diff 代替。
4. 对本阶段可能修改的文件记录原始内容/副本与哈希，支持与阶段起点实际比较。`git stash create` 至多提供已跟踪内容的辅助快照，不包含全部未跟踪/忽略文件，不能声称其 diff 精确等于阶段变更。

基线原始副本放 `.work/` 并按项目规则忽略，避免把备份/日志误提交。持久任务记录保留基线 HEAD、归属摘要及必要内容哈希。限定到任务相关内容，不复制凭据和无关大文件；排除项写明且不能用于声称完整覆盖。缺少安全可用基线时采用逐文件检查并声明限制，不擅自 stash/reset/clean/删除用户内容。

每轮验证记录相关源码、配置、测试及必需输入文件的路径和内容哈希（Git HEAD 仅是附加信息）；未跟踪文件同样计入。用 `evidence/<产物标识>-manifest.*` 保存指纹。日志及状态文件不纳入自引用哈希。验证前后核对指纹：执行本身生成的预期文件注明，其他并发改动使结果失效。非相关修改不必作废所有证据，但必须记录影响判断。

## 证据记录

每条 V 记录下列字段，多个 V 可共享一次真实运行，但要分别解释覆盖：

| 字段 | 要求 |
|---|---|
| V / R / 阶段 | 对应预期集合中的稳定编号 |
| 产物状态 | manifest 路径、时间；必要时 HEAD、输入数据标识 |
| 环境 | 工作目录、工具/依赖版本与相关条件；不输出秘密 |
| 方法与期望 | 确切命令或可复核检查步骤，以及通过条件 |
| 实际 | 原始关键输出/观察结果、真实退出码（适用时） |
| 证据位置 | 原始 stdout/stderr 日志或检查记录路径 |
| 结论与缺口 | 通过/失败/未验证/不适用；差异、限制与剩余事项 |

代码审阅、文档比对或视觉检查可以没有命令退出码，但必须说明检查对象、方法和实际结果。`exit=0` 不能证明未执行的验收项。原始输出保留，汇报用摘要及路径；不能吞掉 stderr。Bash 执行命令时先把 stdout/stderr 写入日志并立即保存 `$?`，再读取日志摘要；若用管道须保留被测命令的退出码，不能误取 tail/tee 的成功码。PowerShell 对原生命令立即保存 `$LASTEXITCODE`，对 cmdlet 使用终止错误并明确成功/异常结果，不能用旧 `$LASTEXITCODE`。

review 与 gate 各记录所覆盖 V 集合、产物 manifest、阻塞项与结论。复查保留旧记录、追加新版本并指明已失效证据。修改代码、配置、测试或验收条件后，重验受影响项目及必要回归，任何决策分支都不能绕过此规则。

## 持久记录与启动迁移

- 唯一权威目录为项目 `docs/longdev/<任务>/`、`docs/autopilot/<产品>/`。PLAN、阶段、决策、review、gate、context、acceptance、验证摘要和 manifest 纳入 Git。原始日志、截图、补丁、备份放项目 `.work/<longdev|autopilot>/<任务或产品>/` 并忽略。持久摘要必须包含 R/V、准确方法、产物哈希、期望/实际、退出码和限制；本机日志链接仅为附加证据。换机器缺失原始证据且无法独立复核时定向重验，不凭历史状态直接放行。
- 启动/续接执行 `skills/longdev/scripts/migrate_workspace.py --project <当前项目根>`；脚本位置以实际安装包为准。安装/升级不扫描工作区，首次使用新版技能时迁移当前工作区。`--check` 完全只读；CLI exit 0=无需迁移/完成，1=只读探测发现待迁移，2=受阻。没有旧记录时不创建空目录。
- 脚本先检查全部冲突、符号链接和忽略规则，再取得工作区独占迁移锁；逐文件原子写入，journal 保存在 `.work/longdev-migration/`。原旧目录完整保留为只读保护副本；中断后相同内容可重试，源或目标被另一个写入者修改时停止并报告，不覆盖。保留状态、决定和全部内容；只重写迁移树内的 Markdown、纯文本及标准库解析后的 JSON 字符串值路径（支持常见相对、绝对和 Windows 路径），业务源文件不改写。项目外部 Markdown/JSON 引用命中只报告，由主会话核对范围后更新具体入口；其它结构化格式（如 YAML/TOML）保留原字节，含旧路径时列入 `manual_review`；机器专属外部路径和链接带复杂语法时人工核对，不宣称全部自动可移植。
- 完成标记为 `docs/longdev/.migration-v013.json`，包含源/目标哈希、移动的本地证据及外部引用待核对列表，不绑定机器绝对根。只有写入校验及 Git ignore 检查通过后才写 complete。此后仅从 `docs/` 恢复，不再导入残留旧目录，不因本机 `.work/` 缺失或持久文件正常后续修改而重写记录。标记和持久记录再次被忽略时仍报受阻。迁移不改变验收状态，也不是接手旧任务的授权。
- 忽略规则命中时，脚本退出 2，不静默 `git add -f`。主会话在项目授权范围内检查规则来源，按命中路径在项目 `.gitignore` 增加最小例外（必要时逐级解除父目录忽略）；不要改全局 ignore 或解除整个客户端目录。复跑迁移及 `git check-ignore` 验证；仍冲突保持受阻。保证 `.work/` 被忽略。非 Git 工作区可迁移但明确无法 Git 同步，不擅自初始化仓库。
- 脚本不执行 `git add`/commit。迁移成功表示文件已迁移、可被 Git 收录，**不表示已经跟踪/提交/远端同步**。主会话核对 `git ls-files`、未跟踪和暂存差异，将本次迁移的持久记录与完成标记纳入下一个已通过 gate 的阶段提交；发现迁移以外的已有记录须先确认归属。另一个机器还需取得这些提交；push 遵守独立授权。

## 阶段本地提交

采用本流程执行开发任务时，默认在每个阶段独立 review 与主会话 gate 均通过后自动本地 commit；用户明确禁止/延后提交或适用更高优先级限制时从其约束，并在 PLAN 记录来源。主会话负责提交，implementer 不在审查前抢先提交。push、发布与部署不由本地提交默认值授权。

1. **先 gate 再记录**：同步阶段状态、R/V 摘要、review/gate、决策和交接，检查持久目录及迁移标记未被忽略。此次代码与记录属于同一个阶段检查点，不能只提交代码留下唯一任务入口未跟踪。
2. **核对归属与索引**：对照阶段起点与最新 `git status --porcelain=v1 -uall`、`git diff --cached --binary`、`git diff --binary`；逐项列出可提交路径/片段。父仓库和 submodule 分别处理。已有 staged 内容不得混入；同文件存在用户/他人改动、任务记录已有不明内容时，不能因为路径属于任务就整文件提交。能安全分离才采用已验证的片段/独立索引流程，否则记“提交受阻”并说明冲突，不 reset/stash/clean，不为制造干净索引覆盖用户工作区。
3. **限定提交**：仅对归属完全明确的新增文件执行显式 `git add -- <路径>`，复核暂存结果。当列表中每个文件的完整内容均属于本阶段时，可使用 `git commit --only -m <消息> -- <明确路径...>`，避免将其它路径的原有 staged 内容提交；不能使用无路径的 `git commit` 或 `git add -A`。如需片段级提交，必须验证独立索引内容与原索引保留情况，不能把部分暂存后整路径 `--only` 当作片段提交。
4. **结果核验与续接**：读取真实退出码，以 `git show --stat` / `git show --name-status` 核对提交文件、内容与父提交，核对原有 staged/unstaged 改动仍在；不得仅凭输出有 SHA 判断成功。消息包含稳定 trailer `Longdev-Task: <任务名>`、`Longdev-Stage: <阶段号或final>`；阶段记录可通过 trailer 找到包含自己的 commit，避免为写自身 SHA 无限追加提交。成功后在对话/下一阶段基线登记 SHA。提交过程中 hook 修改了已验证产物，相关检查失效，先重验；失败记录错误、当前索引变化与解除条件，保持“检查通过 / 提交受阻”，不能静默推进下一阶段或把积压当成功。
5. **明确例外**：用户禁止提交→记录来源后按指示继续；非 Git→记录“不适用：非 Git，尚不支持 Git 跨机器同步”，不自动 init；全部拟提交内容已在当前 HEAD 且归属核对无遗漏→记录“无变化”及依据。未跟踪记录不算无变化。任何工具、权限、签名、hook 或归属阻碍都属于提交受阻，不是无变化例外。下一次续接先核对此提交步骤，避免代码/记录已通过却一直不落 commit。

整体审查/验收及 autopilot 迭代收尾新增的持久记录同样做限定范围的收尾提交；相同产物的有效测试可以复用。提交不代表用户已验收。外部同步沿用已存在的授权和项目发布约定，缺少授权时只交付本地 commit。

## 受限模型的视觉处理与交接

用户反馈的 DeepSeek v4 私有化部署会将请求中的历史与新增图片合并计数，超过 4 张触发 400；限制随模型/服务配置生效，与使用 dsh、Codex 或其他客户端无关。该配置下采用以下约定；其他部署按已确认的能力和上限处理，不把 4 张泛化为所有模型的限制。

- 主会话保持纯文字。图片落盘，优先用可用的 `vision` / `ocr-local` 或等效独立服务取得文字结果；派发、角色交接、review、gate 和 acceptance 只回传文字及文件路径，不嵌入图片。主会话不调用会返回图片的查看、截图或预览入口。
- 不向已确认不支持多模态的目标发送图片；能力未知先查配置或文档，不用发图试探。必须直接看图时使用已确认支持多模态的独立临时会话，仅传文字任务和图片路径，不继承含图历史。确认会话隔离和纯文字返回能力后才使用子 agent；无法隔离则通过独立视觉服务或本地 OCR 处理。
- 私有化视觉临时会话每次只处理一张图片，完整请求不继承含图历史，用完不复用；4 张只记录既有部署上限，不作为单图隔离下的可用额度。主会话历史已含图时，迁移目标、决策、R/V 状态及证据路径到新的纯文字会话，或使用已验证能移除历史图片的机制；不能假定后续只发文字、摘要或归档就能清除图片。缺少恢复机制时记录阻碍，不重复超限请求。
- 视觉证据记录对应 R/V、图片路径/编号及内容哈希、产物版本、检查工具/方法、实际观察、结论和不确定项，原图保留在项目 `.work/longdev/<任务>/evidence/`，持久记录保存路径、哈希和观察摘要。OCR 不能替代布局、颜色、遮挡等视觉理解；视觉能力不可用时相关必需 V 标未验证，不降低验收标准。
- reviewer / final-reviewer / acceptance 需独立复核时，通过上述隔离入口检查原图，不能只认可 implementer 的文字摘要。主会话 gate 负责发起所需验证、核对文字报告、图片指纹、R/V 覆盖与限制；视觉操作通过隔离入口执行，不要求把原图载入主会话。已有独立证据有效且覆盖充分时可复用，缺口需补查；其余必需验证仍由主会话按原流程执行。

## 授权、决策与恢复

记录已有授权、约束与后续明确指示的来源及范围，遵守适用指令优先级。常规技术决策按目标和事实自主处理；跨阶段技术影响需更新相关契约、入口与验证，不自动等同于需要用户批准。仅对缺失的目标意图、超出授权的重大取舍、外部影响或不可逆操作请求决定；不反复确认已有授权。

重要决策写清问题、R/V、事实依据、选项、结论、授权、影响范围、恢复方式与待重验项。决策数量只作观察信息，不能替代风险判断。新建议先记录，未经纳入授权范围不能当成新增任务实施。

失败按产品缺陷、环境/外部依赖、授权缺口区分；保留日志，按新证据修复或重试。不把受阻说成通过，不把自动回滚视为通用恢复方式。恢复仅涉及归属明确且已授权的改动，优先可审阅补丁；依赖失败阶段的工作不得放行。续接和收尾均核对实际产物，而不只相信记录。

## 会话运行时

- longdev 核心不绑定某个客户端。客户端适配、命令探测、会话 ID 和启动参数遵守同目录 `session-runtime.md`；恢复参数必须先由客户端 help 或实际探测确认。
- Codex CLI、Claude Code CLI 和 dsh 可以承担不同任务。每个任务记录当前客户端和会话标识；跨客户端切换必须通过纯文字交接包，不能把一个客户端的 transcript 当作另一个客户端的上下文。
- 运行器若存在，只能编排会话生命周期和传递交接提示；R/V 状态、review、gate、授权和验收仍由 longdev 协议负责。没有运行器时，手动新会话读取同一交接包也属于有效恢复。
- 同一工作目录轮换多个客户端时只保留一个 longdev 任务索引；每次只有一个客户端持有当前阶段写入租约。租约释放、工作区指纹和下一动作写入交接包后，另一个客户端才可接管。
- 客户端与模型配置分开记录。模型切换必须保留模型名、已验证能力、切换原因及受影响 V；不因模型更换降低 R/V、授权或 review/gate 标准。未知能力按未知处理，不能从名称推断视觉、工具或上下文能力。
- 所有阶段优先使用 default 或更强的稳定配置和已支持的 high/更高推理档位，不按角色自动降档。模型输出异常先停止依赖推进并核对有效 checkpoint，保留现场，不自动回滚。
- 私有化多模态模型按单图子会话隔离：主会话保持纯文字，每个无图片历史的子会话最多处理一张图片，只回传文字观察和路径。未知图片上限按可能存在累计限制处理，不向主会话或同一子会话追加图片。
