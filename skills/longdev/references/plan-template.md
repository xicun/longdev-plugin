# PLAN.md 模板（索引）

planner 立项时按此结构写 `<任务目录>/PLAN.draft.md`，用户确认后由主会话改名为 `PLAN.md`。

PLAN.md 是**索引**，不是全部内容。每个 implementer 开工都会全读它，所以这里只放「每个阶段都用得上」的东西：

| 内容 | 放哪 |
|---|---|
| 阶段局部的决策、坑、改动记录 | `stages/N.md` |
| 影响 ≥2 个阶段的决策、任何阶段都会踩的坑 | PLAN.md（本文件） |
| 跨阶段参考物：API 契约、字段映射、状态机、错误码表 | `notes/<主题>.md` |
| 调研的完整报告 | `scout/<主题>.md` |

**硬上限 120 行。** 超了说明有该下沉到 `stages/` 或 `notes/` 的内容——下沉，不要压缩措辞。

```markdown
# <任务名>

**目标**：<一到三句话说明做完之后什么变了。写可观察的结果，不要写"优化""改进"这类空词。收尾审查会拿这一句端到端验。>

**创建于**：<YYYY-MM-DD>　**最后更新**：<YYYY-MM-DD>
**基线 commit**：<立项时 `git rev-parse HEAD` 的输出；非 git 仓库写"无"。收尾审查用它算全量 diff。>

## 阶段

| # | 目标 | 状态 | 入口/记录 |
|---|---|---|---|
| 1 | <一行> | ✅ 2026-08-20 | `stages/1.md` |
| 2 | <一行> | ▶ 当前 | `stages/2.md` |
| 3 | <一行>【主会话】 | ⬜ | `stages/3.md` |
| 4 | <一行> | ⬜ | `stages/4.md` |

<!-- 状态：⬜ 未开始 / ▶ 当前 / ✅ 完成（带日期）。【主会话】= 需要用户现场决策，由主会话亲自执行（SKILL.md 的 D 流程）。 -->

     只影响一个阶段的实现细节决策写进那个 stages/N.md，不要放这里。 -->

- **<决策点>**（立项）：选了 <方案>，因为 <原因>。放弃 <备选> 因为 <原因>。
- **<决策点>**（阶段 N 提升）：...

- <现象> → 原因 <...>，处理 <...>

## 验证方式

**运行命令**：<单个文件/包怎么跑、全量怎么跑。写确切命令。>
```

## 填写纪律

- **索引和阶段文档的分工是这个结构的全部意义**：PLAN.md 胖起来，每个 implementer 开工的固定成本就涨一次。发现某节在长，先问"这条是不是只对一个阶段有用"。
- 决策/坑默认写进 `stages/N.md`。只有 implementer 判断"后面阶段也会用到/也会踩"时才提升到 PLAN.md，并标 `（阶段 N 提升）` 保留出处——收尾审查靠出处查"后期改了决策、早期代码没回头改"。
- 中途冒出的契约类内容（字段映射、状态机、错误码表）建 `notes/<主题>.md`，**不要在 PLAN.md 里新开一节**。
- 相对日期一律换成绝对日期。
- 「阶段」表的状态列是主会话唯一会 grep 的东西，格式不要改。
- 阶段全部完成、收尾审查通过后，在标题下加一行 `**状态：已完成**`。整个任务目录保留作为决策记录。
