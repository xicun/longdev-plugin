# stages/N.md 模板

按 [执行协议](execution-protocol.md) 写给无上下文接手者。入口和实际记录分开；入口调整保留原因、授权及受影响 R/V。8 文件/400 行仅为评估拆分的参考。

```markdown
# 阶段 N：<目标>

## 入口

**关联需求/验收**：R01 / V01（指向 PLAN 或唯一权威表）
**完成标准**：<实际期望，不能只写“测试通过”>
**前置条件**：<已检查通过的依赖和现场事实>
**范围与文件**：<计划修改的文件、边界及不涉及部分>
**验证方法**：<V 的确切命令/检查步骤，环境及预期结果>
**参考/契约**：<路径、章节和用途>
**风险**：<必要回归、兼容性、外部依赖>
**阶段起点基线**：项目 `.work/longdev/<任务>/baselines/stage-N/`（主会话核实）；持久 HEAD/哈希/改动归属摘要：<位置>

## 入口变更记录

- <日期、事实/用户依据、影响 R/V 与阶段；无则写无>

## 执行记录

**实施日期/状态**：<日期> / 待检查
**实际改动**：<路径、内容、对应 R；包括新增未跟踪文件>
**测试/检查**：<验证行为；未新增测试的依据>
**局部决定**：<事实、授权与影响；共享决定链接 PLAN/decisions>
**问题与处理**：<失败原因、修复过程、未解决事项>

## 自检证据

**产物 manifest**：`evidence/<run>-manifest.json`（也可用项目已有可核查格式）

| V ID / R ID | 环境与方法 | 期望 | 实际/退出码（适用时） | 原始证据路径 | 结果/缺口 |
|---|---|---|---|---|---|
| V01 / R01 | <目录、工具版本、确切操作> | <结果> | <可跨机器复核的关键结果/真实退出码> | 项目 .work/longdev/<任务>/evidence/<run>.log | <通过/失败/未验证/不适用及依据> |

## 修复与复查交接

- <修复内容、受影响 R/V、新 manifest/证据、已失效记录；无则写无>
- review：`reviews/stage-N.md`；gate：`gates/stage-N.md`（主会话维护结论）

## 阶段提交（主会话）

- 先决条件：<当前独立 review/gate 路径；记录已同步；Git ignore/跟踪检查>
- 归属与保护：<明确路径/片段、基线对照、原 staged/同文件他人修改的处理>
- 提交定位：消息 trailer `Longdev-Task: <任务名>`、`Longdev-Stage: N`；SHA 在提交后汇报/下一阶段基线登记，避免自身 SHA 自引用循环。
- 实际结果：<待 gate / 可由包含此记录的 commit 核验 / 提交受阻及原因 / 用户禁止的来源 / 无 Git或无变化的依据>；失败不得静默进入下一阶段。

## 给下一阶段的交接

- <当前已形成的接口/契约/文件及必须知道的限制>
- <尚未满足的依赖，不得当作已完成前提>
```

自检通过仍是待检查。后续修复追加新证据并使受影响旧证据失效；独立 review/gate 未通过前不能启动依赖本阶段的实现。相同产物和条件下已有有效检查不无理由重复。
