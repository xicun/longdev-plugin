# 需求分析与方案设计

主会话可直接使用本技能；复杂且边界明确的独立分析可委派 [requirements-designer](../../agents/longdev-requirements-designer.md)。方法以本文件为唯一来源，角色说明只规定输入、写入范围和交接。

## 目标与记录边界

- 先识别用户本轮需要的是解释、讨论结论、可评审设计，还是已授权的开发任务。纯讨论直接在对话中形成完整结论，不要求先建 PLAN、任务目录或调用迁移脚本；讨论目标达到即结束，不自行扩成开发。
- 只有用户授权形成持久设计文档（含已授权开发任务所需设计记录）时才写文件。优先复用已有设计来源和用户指定位置；longdev 内按其协议/路径 guard 使用 `notes/analysis-design.md`，格式可参考 [分析设计模板](../longdev/references/analysis-design-template.md)。独立文档不要求为了使用本技能创建 longdev 目录。
- 承接既有稳定 R/V ID 和来源，不重新编号。没有编号且需要持久追踪的新项才分配 ID。已有 PLAN/需求文件是事实源时，设计只引用其 ID 并补设计映射；新建详细需求源时 PLAN 只维护索引、执行状态与 V 映射，不复制第二套可独立编辑的需求。假设、待决定项不能写成已确认需求。

## 分析方法

1. 明确问题、使用者/调用方、场景、可观察目标、成功标准、范围和非目标；复用已有决定与授权，发现冲突时指出来源及影响。
2. 补齐正常流程、边界/失败行为和关键约束。设计深度跟随风险：说明必要的交互、接口、数据、组件、兼容与恢复方案，不为简单问题补整套章节。
3. 对影响方案的未知做有边界的事实核查或最小实验，保留证据、反证和剩余限制。足够判断即停止探索，不把未验证候选包装成成熟方案。
4. 建立需求→设计→验证思路的映射，检查遗漏、矛盾、无依据新增及外部影响。只把影响目标、重要取舍或授权的缺口交用户决定，明确问题、影响及有依据的推荐；继续不依赖答案的工作。
5. 交付符合本轮目标的完整结论或可评审设计，区分事实、用户决定、推断和未知。有实施授权且无关键待决定项时继续交给 planner 建立 V、阶段和依赖；没有实施授权时以设计交付结束，不问泛化的“是否继续”。

## 连续推进与收敛

小结、章节结束、角色交接或局部问题解决不构成停顿理由。调查与验证调用遵守执行协议的 [调查收敛与工具异常](../longdev/references/execution-protocol.md#调查收敛与工具异常)：调用前明确判定项与预期信息，结果后把结论、有效证据和下一动作物化到现有记录，纯问答在对话中说明，不强制建档；已有有效证据且相关产物、环境及验收条件不变时复用，不重复跑成功验证；相同调查/验证无新依据地连续重复，或连续三次调用无新事实、证据缺口收敛或推进依据时，停止该路径并形成收敛决定。有可追踪在途工作、按宿主接口进行且设有复核时点的正常异步等待不计入三次无新事实阈值（协议豁免条款）；必要依赖缺失才交接/受阻，只有具体关键缺口才提问，不把阈值变成例行确认点。

## 工具结果判断

- 按工具协议、真实退出码和预期语义判断结果：成功但无 stdout 可以正常；有任务/会话 ID 的 `pending` 是异步待完成，应使用该工具的恢复接口，不重复启动同一动作。
- 预期结果缺失、`no tool`、工具不可用或适配器异常且无法证实成功时，记为运行时/适配器异常或未验证；保留原始错误、调用上下文、ID/退出码和影响范围，不把它改写成需求含糊或未完成。重试与恢复限制同协议；写工具不可用时在对话保留交接，不循环尝试写入。
- 上述是结果分类与恢复方法，不对任何模型（包括 GLM）的能力作事实断言；实际能力未知时如实标为未知。

## longdev 与 autopilot 接口

- longdev 需要持久编排时再读其 [执行协议](../longdev/references/execution-protocol.md)。设计 gate 核对需求覆盖、可行性、边界、兼容和关键未决项；planner 消费既有需求/设计，testcases 在行为与 R/V 稳定后设计用例，reviewer 按风险独立审查。设计通过不代替实现检查或用户验收。
- autopilot 的 product-owner 保持产品目标、宪章、预算和 backlog 的所有权；本技能仅收敛已选任务的需求/设计，引用原 G/V/R，不重复建立产品目标或扩展授权。
- 旧任务已有充分设计时直接复用；只在安全交接点补后续缺口，不因技能升级重开已验收任务、重编号、改历史授权或使无关证据失效。
